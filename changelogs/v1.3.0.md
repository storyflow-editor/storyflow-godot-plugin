##### New Features

- **Data Assets in Godot**: Import a StoryFlow Editor project with `.sfd` Data Assets and the plugin loads their variables, parent relationships and referenced media. A child reads the nearest value in its inheritance chain, including a value changed during play. Runtime writes belong to the current session and never rewrite the authored Data Asset

- **Data Asset Nodes in Dialogue**: Get Data Asset, Get Data Asset Variable and Set Data Asset Variable nodes read and change those values from a story graph. A boolean asset value can decide whether an option appears. Add To, Remove From, Clear and Set Array Element also write through an asset accessor when their array input comes from one. Get Data Asset Variable Names lists declarations from the parent chain

- **GDScript Access to Data Assets**: `StoryFlowComponent` and the `StoryFlowRuntime` autoload expose typed get and set methods for bool, int, float, string and enum values. Pass a stable asset ID or a unique display name and the declared variable name. `get_data_asset_variant()` reads arrays and maps; `set_data_asset_array()` and `set_data_asset_map()` replace them with type-checked values. Game code can use these methods without an active dialogue

- **Data Asset Changes in Save Slots**: Values written during play are included in saves alongside story, global and character state. Loading restores them, and `reset_all_state()` returns them to their imported values. Saves from older Godot plugin versions still load; a save written by this version is not readable by a plugin version before v1.3.0

- **Stable Character IDs**: Current StoryFlow Editor exports include `character-index.json`. Dialogue and character-variable nodes use an ID when one is present, so a character file can move or be renamed without changing the binding. `get_character_by_id()`, `get_character_variable_by_id()` and `set_character_variable_by_id()` make the same lookup available to GDScript. Older path-based exports and calls remain supported

- **Project-Wide Localization**: Import `localization.json` to read authored dialogue, character names and declared Data Asset strings in the selected language. Use `StoryFlowRuntime.get_languages()` to build a picker, `set_language()` to select a code and `get_language()` to read it. The `language_changed` signal lets your UI refresh text it has already drawn. Runtime-written text, Data Asset overrides and identifiers remain literal, and save slots do not store the player's language preference

- **Audio-Driven Lip Sync**: Add a `StoryFlowLipsync` node to a character scene, set its StoryFlow dialogue source and bind the face with a stable character ID. It analyzes dialogue audio as it plays and moves existing ARKit-style mouth blendshapes without a timing track or face-tracking hardware. Face Root can include separate head, teeth and tongue meshes. A `StoryFlowVisemeMap` resource lets a different rig choose its own shape names and weights, and strength, sensitivity, jaw bias and smoothing tune the result. The node can also follow an `AudioStreamPlayer`, `AudioStreamPlayer2D` or `AudioStreamPlayer3D` started by game code

##### Improvements

- **Data Asset Media Resolves Across Scripts**: Images and audio referenced by a Data Asset join the shared project asset pool. A value remains usable even when the current dialogue script did not reference that file itself

- **One Runtime Data Asset View**: Component calls and `StoryFlowRuntime` calls read and write the same session values. An asset can be addressed by ID or a unique name, and declared variable names can be listed without keeping a second list in game code

- **Lip Sync Manages Its Audio Route**: For ordinary dialogue playback, the node creates an analysis route for the active player and restores its original bus when the last listener releases it. A dedicated Analysis Bus can be supplied for custom audio routing. The mouth returns to rest when playback pauses or ends, and it can follow audio that continues after the dialogue line finishes

- **Broken Data Asset Bindings Fail Clearly**: If an asset or declared variable is missing, or a node's saved type no longer matches, the node uses its type default or refuses the write and warns once rather than silently changing another value

##### Bug Fixes

- **Character Names and Portraits Survive Save and Load**: A character's Name and Image changed during the story now return when the save is loaded, instead of reverting to the imported values

- **Save Loading Does Not Stay Blocked After a Dialogue Ends**: A component freed during dialogue or started on another script releases its previous active registration. Later loads no longer remain blocked by a conversation that is no longer running

- **For Each Keeps Its Current Element During Dialogue**: When a dialogue appears inside an array loop, its option conditions and following nodes can still read the element for that iteration

- **Live Project Reloads Keep Globals Connected**: Re-importing a project during an active dialogue no longer leaves that dialogue reading an abandoned copy of the global variables while new writes go elsewhere

- **Data Asset Values Stay Intact**: Reading an array or map cannot mutate the stored value through an accidental shared reference, and repeated writes or save restoration keep the current session's values

- **Localization Does Not Rewrite Runtime Identities**: Language lookups translate authored strings while leaving character references, map keys and other game-facing identifiers intact

##### Breaking Changes

- **Direct Save Helper Calls Need Data Asset Arguments**: Game code calling `StoryFlowSaveData.save_to_slot()` directly must now provide the Data Asset seed and current session values. Calls through `StoryFlowRuntime.save_to_slot()` and `load_from_slot()` keep their existing signatures
